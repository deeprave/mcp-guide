## Why

`additional_agent_instructions` is currently placed on `Result`, although it is generated by a session TaskManager queue and is unrelated to the value, success, failure, disposition, or instruction of the response it is attached to.  Mixing it into the result payload obscures this boundary and makes response semantics inaccurate.

## What Changes

- Move queued additional agent instruction delivery from `Result` to response metadata.
- Deliver all currently queued additional agent instructions as one FIFO-ordered list with each outgoing response.
- Deliver the queued instruction through a clearly Guide-namespaced `_meta` value on tool, prompt, and resource responses, independently of the Guide result payload.
- Keep result-specific `instruction` and `disposition` in `Result`.
- Trial list delivery while documenting that list order is delivery order only, not priority or an instruction to action the first item before the others.

## Capabilities

### New Capabilities
- `response-metadata`: Defines Guide response metadata as side-band transport information and establishes its public metadata contract.

### Modified Capabilities
- `task-manager`: Queue one independent agent instruction for delivery without modifying the produced result.
- `tool-infrastructure`: Keep the canonical Result payload result-specific while propagating response metadata consistently through the public adapters.

## Impact

- Affects `Result`, TaskManager result processing, result dispatch helpers, FastMCP adapters, and tool/prompt/resource response tests.
- **BREAKING**: `additional_agent_instructions` will no longer appear in Guide's structured result payload or `guide_result` metadata; clients must read the Guide-namespaced response metadata list instead.
- Does not implement cache policy or cache settings.
